# 持证上岗统计分析系统 · 可演示 MVP

管理端系统演示：**数据接入 → 名称治理 → 作业范围确认 → 已发布规则版本 → 三值规则计算 → 质量 / 预警 / 合规三类问题 → 整改复核销项 → 驾驶舱三项口径**。

> 宁可标记「未知、待确认、数据不足」，也不得根据不充分信息自行推断正式合规结论。

在线体验（GitHub Pages）：**https://inori-3333.github.io/chd-license-manager/**

本仓库是方案文档中的 **MVP**（纯前端、可在 Pages 上打开）。完整企业级后端、人资接口、统一认证不在本演示范围内，但规则引擎、标准化漏斗、整改闭环与统计口径按方案实现。

## 这套 MVP 证明什么

- 不是把 Excel 换成网页台账，而是可配置、可版本化、可解释的持证资格计算。
- 原始组织 / 岗位 / 证书名称不被覆盖。
- AI / 算法只推荐标准名称候选，**不能**自动映射、不能补作业范围、不能下合规结论。
- 数据不足时输出「无法判定」，该人员不进入人员合规率分母，由统计覆盖率单独暴露。
- 基层不能自行销项；销项后重新计算。

## 建议 8 分钟演示路径

1. **管理驾驶舱**：同时看人员合规率、应持证项完成率、统计覆盖率。覆盖率不足是因为存在未标准化名称和缺失作业范围。
2. **数据导入**：下载带非法行的 Excel 模板并上传，观察「部分成功」——合法行进入、非法行进错误清单。
3. **名称标准化**：确认「电修技术员 → 电气检修技术员」「注安师 → 注册安全工程师证」「生技部 → 生产技术部」。必须点确认，推荐不会自动生效。也可点「都不正确」。
4. **人员持证**：打开「郑华」，补充作业范围「高压电气作业」。系统不会根据岗位自动填写。
5. **规则中心**：查看高压规则 v1 / v2 历史；HR 角色审核「电力电缆作业」草稿；尝试发布「冲突草稿」会被阻止。
6. **问题中心**：区分数据质量、风险预警（180/90/30/7 天临期）、合规问题（应持未持 / 过期 / 复审逾期）。每条都有判定依据。
7. **整改闭环**：切换「赵班长」开始整改并提交；切换「李人资」指定复核人；切换「钱安全」复核通过销项。基层看不到销项按钮。
8. 回到驾驶舱，观察口径与问题数变化。右上角可改**统计时点**做历史重算（例如 `2024-06-01` 会落到高压规则 v1）。

右上角角色切换是演示用入口。数据保存在本机 `localStorage`，可随时「重置演示」。

人员与组织来自仓库中的 `岗位示例表.xlsx`（公司 / 部门 / 班组 / 岗位，共 1315 条）。每人对应表中一条岗位；持证、作业范围和演示用例（临期、应持未持、学习岗待治理等）按专业规则叠加，以便走通闭环。

## 种子数据已覆盖的场景

标准岗位与非标准岗位、非标准证书、同名/近似组织、作业范围缺失与完整、正常持证、应持未持、180/90/30/7 天临期、已过期、复审逾期、调岗、兼岗、群体比例达标/不达标、新上岗过渡期、规则版本、非法导入、合法但待治理。

## 技术说明

- React 18 + TypeScript + Vite，Hash 路由，可部署到 GitHub Pages。
- 规则条件是受控 JSON，执行器只识别白名单字段和操作符。
- 三值逻辑：`True AND Unknown = Unknown`，`False AND Unknown = False`。
- 名称推荐是可降级本地算法（别名词典 + 编辑距离），生产环境可替换为 LLM，输出仍须落在标准库候选集内并由人工确认。
